# 石之迷宫 · THE STONE LABYRINTH

> 一个放在白色桌面上的黑暗童话微缩迷宫。**真正的 Three.js 3D 场景**，固定正交相机，低模石材与低分辨率像素渲染。

不含任何电影素材、第三方模型、图片贴图或音频文件。场景、迷宫算法、角色和音效全部由代码生成。灵感来自古老石井与黑暗童话迷宫意象；这是原创互动原型，不是电影官方作品。

## 已完成（Chapter I — 遗忘之井）

- **可玩的 19×19 石迷宫：** 伪随机深度优先生成，固定 seed 保证每次同一张图；迷宫是连通树，路线具有唯一性。
- **三道真正会沉降的石门：** 门在解封前不可穿越，在解封后从三维世界中下沉。
- **三枚需要转向的符印：** 找到符印石台，查看石碑的方向提示，将符印旋到正确朝向；完成后远处机关开启。
- **角色移动：** WASD / 方向键逐步移动；点击可达石砖，沿真实最短路自动寻路；点击符印会走过去并执行交互。
- **移动端支持：** 方向键 + 交互按钮；相机在竖屏自动跟随角色，保持固定等距角度。
- **完整游戏循环：** 开始界面、游玩 HUD、进度、提示、音效、通关页面、重开。
- **纯程序视觉：** Three.js geometry、色块材质、程序枯树、石墙、低模角色、浮空符石与光源；无贴图或外部模型。
- **像素输出：** 内部以更低分辨率绘制，然后通过 `image-rendering: pixelated` 放大，保留干净的像素边界。
- **自动化验证：** 测试关卡生成、可达性、机关顺序及不同随机种子下的解谜连通性。

## 本地启动

需要 Node.js 20.19+ 或 22.12+。

```bash
npm install
npm run dev
```

打开终端显示的本地地址（一般为 `http://localhost:5173`）。

```bash
npm test      # 关卡逻辑测试
npm run build # 生成 dist/ 静态网站
npm run preview
```

## 操作

| 操作 | 方式 |
| --- | --- |
| 前进一步 | W A S D 或方向键 |
| 自动寻路 | 点击迷宫内可达的石砖 |
| 旋转符印 | 在石台旁按 E / Space，或触摸“交互” |
| 走到符印旁 | 点击或触摸符印本身 |
| 缩放 | 画面右上角 `+/-`，桌面鼠标滚轮 |
| 重玩 | 右上角 `↻` |

**解谜目标：** 迷宫里有三枚分散的符印，石碑提示各自应指向的方位，旋转到正确朝向后对应石门下沉。三枚全部归位后，走到最远端的古井，即可通关。

## 关于画风

这是 **低多边形三维模型 + 像素化输出**，不是把二维 SVG 放在屏幕里假装成三维，也不是 `isometric` 平面伪透视。镜头由 Three.js 的 `OrthographicCamera` 实时渲染模型，石墙、古井、树木、石台有真实的三维厚度与阴影。

风格约束：白背景、冷灰石材、苔藓墨绿、少量月紫冷光；禁止黄旧纸质感、塑料皮肤、无序碎闪、过密粒子、锐化过度、发黄的暖光。

## GitHub Pages

本仓库已经准备好 GitHub Actions 自动部署工作流：

1. 在仓库 `Qisi3344/pixel-pans-labyrinth` 的 **Settings → Pages** 将 Source 设为 **GitHub Actions**。
2. 提交到 `main` 后，工作流会安装依赖、运行测试、生成 `dist/` 并部署。
3. 部署完成后，预期入口是 `https://qisi3344.github.io/pixel-pans-labyrinth/`（实际请以 Pages 页面显示的部署状态为准）。

**注：** 浏览器直接打开本地 `index.html` 不能运行 ES Module；须通过 Vite 开发服务器或部署后的网页访问。

## 当前已知限制

- 当前是第一章 MVP，不含电影角色或剧情重演。
- 低分辨率渲染采用 canvas 缩放而非多通道 Shader 后处理；没有做轮廓描边、Bayer 抖动或复杂体素贴图。
- 移动端主打点击寻路，触摸方向键为单格步进；不支持双指缩放。
- 迷宫机关是“寻找 + 方向旋转”的简单入门难度，后续可以增强为多层互锁。
